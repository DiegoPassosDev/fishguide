# Roadmap de Desenvolvimento

- **Projeto:** FishGuide
- **Versão:** 1.0

## 1. Objetivo

Definir uma estratégia evolutiva para o desenvolvimento do FishGuide, priorizando a entrega contínua de valor sem comprometer a visão de longo prazo.

## 2. Filosofia

O desenvolvimento seguirá quatro princípios.

**Construir o núcleo primeiro**

Primeiro criamos o cérebro.

Depois adicionamos funcionalidades.

**Dados antes da IA**

A IA depende de dados.

Portanto:

- Primeiro:
- usuários; 
- pescarias; 
- histórico. 

Depois:

- Machine Learning. 

**Crescimento modular**

Cada nova funcionalidade deverá ser adicionada como um módulo independente.

**Evolução constante**

Nenhum algoritmo será considerado definitivo.

## 3. MVP

O MVP deverá responder uma pergunta simples.

**Vale a pena sair para pescar hoje?**

Se conseguir responder isso com qualidade.

O MVP já será um sucesso.

## 11. Critérios de Conclusão

Uma funcionalidade só será considerada pronta quando possuir:

- testes; 
- documentação; 
- responsividade; 
- acessibilidade; 
- monitoramento; 
- tratamento de erros. 

## 12. Estratégia de Lançamento

**Alpha**

Uso exclusivo do desenvolvedor e convidados.

Objetivo:

- validar arquitetura. 

**Beta Fechado**

Grupo reduzido de pescadores.

Objetivo:

- validar recomendações. 

**Beta Público**

Disponível para qualquer interessado.

Objetivo:

- coletar dados. 

**Lançamento Oficial**

Primeira versão estável.

## 13. Métricas de Sucesso

Mais importantes do que número de downloads.

Quantidade de pescarias registradas. 

Qualidade dos registros. 

Precisão do FG Score. 

Tempo médio de uso. 

Retenção de usuários. 

Crescimento da Memória Coletiva. 

Evolução do Nível de Confiança. 

## 14. Dívida Técnica

A cada grande versão haverá um ciclo dedicado exclusivamente a:

- refatoração; 
- otimização; 
- atualização de dependências; 
- melhoria da arquitetura. 

Isso evita que a plataforma se torne difícil de evoluir.

## 15. Estratégia de Testes

Além dos testes automatizados, teremos validações em campo.

Exemplos:

- comparar previsões com resultados reais; 
- validar o FG Score em diferentes regiões; 
- acompanhar feedback de pescadores experientes. 

Esses testes são tão importantes quanto os testes de software.

## 16. Preparação para Escala

A arquitetura será preparada desde o início para:

- múltiplos estados brasileiros; 
- água doce e água salgada; 
- diferentes idiomas; 
- múltiplas moedas (caso futuramente exista marketplace); 
- crescimento internacional. 

## 17. Estratégia Comercial

Embora o foco inicial seja construir um excelente produto, a arquitetura permitirá modelos de negócio como:

- plano gratuito; 
- assinatura Premium; 
- marketplace de equipamentos; 
- parcerias com guias de pesca; 
- integração com marinas e pousadas; 
- APIs para parceiros. 

Esses recursos poderão ser ativados no momento adequado.

## 18. O recurso que considero mais importante para o lançamento

**Modo "Aprendizado"**

Nos primeiros meses, o FishGuide deverá informar ao usuário:

- **"Estamos aprendendo com suas pescarias para tornar as recomendações cada vez mais precisas."**

Isso cria expectativa correta.

O usuário entende que está ajudando a construir uma plataforma inteligente.

Ao mesmo tempo, o sistema passa a coletar dados de alta qualidade.

## 19. O que eu mudaria no Roadmap

Depois de toda essa documentação, eu não faria o lançamento baseado em funcionalidades.

Eu faria baseado em **capacidades**.

Por exemplo:

- **Capacidade 1**

O FishGuide entende o ambiente.

(Clima + Maré + Lua + Sol + Pressão)

**Capacidade 2**

O FishGuide entende a pescaria.

(DNA + Timeline + Capturas)

**Capacidade 3**

O FishGuide entende o pescador.

(Histórico + Preferências + Estatísticas)

**Capacidade 4**

O FishGuide entende a comunidade.

(Memória Coletiva + Reputação + Confiança)

**Capacidade 5**

O FishGuide ajuda a decidir.

(FG Score + Decision Engine + IA)

Essa forma de pensar mantém o foco no valor entregue ao usuário, e não apenas em listas de funcionalidades.
